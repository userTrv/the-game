# Настройка перед запуском

Чек-лист того, что нужно сделать руками. Код готов и на моках работает целиком; ниже — подключение настоящих
сервисов. Секреты кладутся только в `.env` на сервере, в репозиторий и в чат их не отправлять.

## 1. Бот в BotFather

1. `/newbot` — создать бота, сохранить токен в `BOT_TOKEN`.
2. `/setuserpic`, `/setdescription`, `/setabouttext` — оформление. Иконка лежит в `apps/client/public/icon-512.png`.
3. Команды бот выставляет сам при старте (`/start`, `/play`, `/settings`, `/paysupport`, `/terms`, `/help`).
4. `/setdomain` — указать домен игры. Без этого не заработает вход через Telegram на сайте.

## 2. Mini App

1. В BotFather: `/newapp` (или Bot Settings → Configure Mini App) — указать адрес игры `https://<домен>/`.
2. Bot Settings → Menu Button — тот же адрес, чтобы игра открывалась кнопкой в чате.
3. Имя бота без `@` записать в `BOT_USERNAME`: оно попадёт в клиент при сборке (ссылки «Открыть в Telegram»,
   приглашения, виджет входа).

## 3. Домен и HTTPS

1. Завести DNS-запись на сервер.
2. Telegram открывает Mini App только по HTTPS с действующим сертификатом.
3. Пример конфигурации — `deploy/Caddyfile.example`. Он рассчитан на сервер, где порты 80 и 443 заняты
   SNI-роутером: Caddy слушает `127.0.0.1:8443`, роутер передаёт туда TLS по имени домена.
4. Сертификат: в такой схеме Caddy не владеет портами 80/443, поэтому нужен DNS-challenge, проброс ACME через
   роутер или готовые файлы сертификата. Варианты описаны в комментариях примера.
5. Перед перезагрузкой проверить: `caddy validate --config /etc/caddy/Caddyfile`.

## 4. Переменные окружения

Скопировать `.env.example` в `.env` и заполнить. Обязательные:

| Переменная | Что это |
|---|---|
| `BOT_TOKEN` | Токен из BotFather. Нужен и серверу (проверка подписи Telegram), и боту |
| `INTERNAL_SECRET` | Длинная случайная строка, общая для сервера и бота |
| `JWT_SECRET` | Длинная случайная строка для подписи сессий |
| `DATABASE_URL` | Адрес Postgres |
| `PUBLIC_URL`, `MINI_APP_URL` | Публичный адрес игры |
| `BOT_INTERNAL_URL` | Как сервер достаёт бота (`http://bot:8082` в одном compose) |
| `SERVER_INTERNAL_URL` | Как бот достаёт сервер (`http://server:3000` в одном compose) |
| `SUPPORT_CONTACT` | Контакт поддержки, его показывает `/paysupport` |
| `ADMIN_PASSWORD` | Пароль админки. Пустой — админка выключена |

Случайную строку можно получить так: `openssl rand -base64 48`.
`DEV_AUTH` в бою должен быть `false` (compose выставляет это сам): он включает служебные адреса `/api/dev/*`.

Пароль Postgres для compose кладётся в файл `secrets/pg_password.txt` (папка в `.gitignore`) и тот же пароль —
в `DATABASE_URL`.

## 5. Запуск

```bash
docker compose build
docker compose up -d postgres server
docker compose --profile bot up -d bot
```

Миграции базы сервер применяет сам при старте. Сервер слушает `127.0.0.1:3000`, наружу его выводит Caddy.

Проверка: `curl -s http://127.0.0.1:3000/health` должен вернуть `{"ok":true}`.

## 6. Где запускать бота

Бот ходит в `api.telegram.org`. Если с игрового сервера Telegram недоступен, бота запускают на другом сервере.

- На втором сервере нужны тот же репозиторий и `.env` с `BOT_TOKEN`, `INTERNAL_SECRET`, `SERVER_INTERNAL_URL`,
  `MINI_APP_URL`, `SUPPORT_CONTACT`. Запуск: `docker compose --profile bot up -d bot`.
- Сервер и бот должны видеть друг друга по закрытому каналу (VPN, WireGuard, туннель). `SERVER_INTERNAL_URL`
  и `BOT_INTERNAL_URL` указывают на адреса в этом канале.
- Порт бота 8082 и адреса `/internal/*` сервера нельзя открывать в интернет. `BOT_INTERNAL_BIND` задаёт адрес,
  на котором бот слушает; по умолчанию `127.0.0.1`.
- Режим `BOT_MODE=polling` не требует входящих соединений от Telegram. Для `webhook` нужны `WEBHOOK_URL`
  (HTTPS) и `WEBHOOK_SECRET`; бот принимает обновления на `/telegram/webhook`.

## 7. Telegram Stars

1. Отдельно включать Stars не нужно: бот выставляет счета в валюте `XTR` без платёжного провайдера.
2. Убедиться, что `/paysupport` и `/terms` отвечают: Telegram требует их для ботов с платежами.
3. Сделать пробную покупку самого дешёвого товара и проверить, что он выдан, а платёж появился в админке
   («Платежи»).
4. Возврат делается кнопкой в админке. Он возвращает звёзды через `refundStarPayment` и забирает выданное.
5. Вывод заработанных звёзд настраивается в BotFather (Bot Settings → Payments / Balance).

## 8. Реклама AdsGram

1. Зарегистрировать приложение в кабинете AdsGram и создать блок с наградой (Rewarded).
2. Идентификатор блока записать в `ADSGRAM_BLOCK_ID` и пересобрать образ сервера: значение попадает в клиент.
3. Придумать `ADS_REWARD_SECRET` (случайная строка) и записать в `.env`.
4. В настройках блока указать Reward URL:
   `https://<домен>/api/ads/reward?secret=<ADS_REWARD_SECRET>&userid=[userId]`
   `[userId]` AdsGram подставит сам. Адрес с секретом никому не показывать.
5. Проверить: посмотреть ролик за ежедневный сундук в лавке и убедиться, что награда пришла.

Пока `ADSGRAM_BLOCK_ID` пуст, кнопки с рекламой в бою не показываются.

## 9. Админка

Адрес: `https://<домен>/admin/`. Вход по `ADMIN_PASSWORD`. Разделы: метрики, игроки (поиск, выдача ресурсов),
события (событие недели, Кракен, сезон), рассылки (с подсчётом получателей перед отправкой), платежи и возвраты.
Стоит закрыть `/admin/` дополнительно на уровне Caddy (по IP или basic auth).

## 10. События

Сервер при старте сам ставит расписание по умолчанию: события недели по кругу (`jelly_bloom`, `pearl_tide`,
`glow_night`), Кракена и сезон. Изменить даты и награды или добавить своё событие можно в админке, раздел
«События»: конфиг в JSON с обязательными `id`, `startsAt`, `endsAt` (в миллисекундах). Поля конфигов описаны в
`packages/shared/src/liveops.ts`.
